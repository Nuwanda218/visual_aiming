# V2 架构设计文档

## 设计理念

借鉴计算机网络的分层架构思想，将项目拆分为**流水线式的处理层次**。与网络分层的包裹/封装结构不同，本项目采用**线性流水线结构**——数据从一端进入，经过每一层处理后传递给下一层，最终产生输出。

核心目标：
- **可理解性**：看到某个文件就知道它在哪一层、管什么事，每一层的输入输出一目了然
- **可替换性**：在可理解性的基础上，任何一层的内部实现可以调整或替换，不影响其他层

## 六层架构

| 层 | 英文名 | 中文 | 类型 |
|---|---|---|---|
| 交互接入层 | `interaction` | 交互接入 | 入口层 |
| 运行编排层 | `runtime` | 运行编排 | 编排层 |
| 图像获取层 | `capture` | 图像获取 | 流水线第 1 级 |
| 视觉感知层 | `perception` | 视觉感知 | 流水线第 2 级 |
| 控制执行层 | `actuation` | 控制执行 | 流水线第 3 级 |
| 共享模型层 | `shared` | 共享模型 | 公共基础 |

### interaction — 交互接入层

对接用户，解析配置，组装各层组件，启动运行。不做任何算法计算。

### runtime — 运行编排层

驱动流水线循环，管理各组件的生命周期（创建、启动、关闭），决定各级的调度方式。不知道流水线内部怎么处理数据。

### capture — 图像获取层

从数据源（视频文件、屏幕截图、内存测试数据）读取原始图像，做 ROI 裁切、色彩格式转换等预处理，输出一帧可以直接用于识别的图像。不知道检测器怎么工作。

### perception — 视觉感知层

接收一帧预处理好的图像，调用检测器进行推理，将原始输出转换为干净的结构化检测结果列表。不选择目标，不做控制决策。

### actuation — 控制执行层

从一组检测结果中选出最佳目标，计算目标位置与准星的误差向量，生成控制指令，交给输出后端执行。不知道图像长什么样，只看到结构化的 Detection 数据。

### shared — 共享模型层

定义各层之间传递的数据结构、层间协议接口、公共配置。被所有层依赖，自身不依赖任何业务层。

## 整体结构

```
┌──────────────────────────────────────────────────────┐
│  interaction（交互接入层）                              │
│  对接用户 → 组装组件 → 启动 runtime                     │
└───────────────────────┬──────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────┐
│  runtime（运行编排层）                                  │
│  循环驱动流水线，管理生命周期，决定调度方式                 │
│                                                       │
│    每一帧：                                            │
│    ┌────────┐   ┌────────────┐   ┌────────────┐      │
│    │capture │──→│ perception │──→│ actuation  │      │
│    └────────┘   └────────────┘   └────────────┘      │
│                                                       │
└───────────────────────────────────────────────────────┘

shared（共享模型层）── 被所有层依赖，定义公共数据结构与协议
```

## 执行原则

各级之间通过数据传递解耦，不假设同步执行。runtime 层负责决定各级的调度方式（同步串行、异步缓冲、独立频率），流水线各级本身不感知也不依赖执行方式。

这意味着：
- 最简实现可以是同步串行（最容易调试）
- 未来可以改成异步（各级独立运行），只需要改 runtime 的调度策略
- capture / perception / actuation 的代码不因调度方式改变而改变

## 层间关系规则

- `shared` 不依赖任何业务层
- 流水线各级（capture → perception → actuation）只通过 `shared` 中定义的数据结构通信
- `runtime` 驱动流水线，但不知道各级的内部实现
- `interaction` 组装一切，交给 `runtime`

## 设计约定

- **准星位置：** 默认画面正中心。capture 以屏幕中心为截取矩形中心，画面中心即准星。如需修改，通过 actuation 的配置入口调整。
- **图像尺寸：** 配置信息，初始化时确定，不随帧传递。capture 保证每帧输出相同尺寸。
